# Requirement Pulse · 产品与界面设计

> 状态：设计基线 v0.1  
> 日期：2026-11-26  
> 产品名：Requirement Pulse（需求脉冲）  
> 形态：Windows 桌面应用（Electron），本地优先，单用户  
> 设计路线：Product register · Instrument workbench · Warm paper / graphite / signal lime

---

## 1. 一句话

**Requirement Pulse 是一块“人给意图、Agent 给判断、人做决定”的需求决策台。**

它把散落在聊天、Issue、灵感笔记里的需求收进一个本地看板；把需求上下文通过本机 Agent Bridge 交给 Claude Code、Codex、DeepSeek Harness 等会写代码的 Agent；再把它们的可行性判断、风险、开放问题和建议步骤，以可比较、可采纳、可追溯的方式落回同一张需求卡。

### 1.1 要解决的问题

一个技术型独立开发者/小团队在使用多个编码 Agent 时，典型断点不是“Agent 不会写代码”，而是：

1. **意图没有稳定载体**：需求散在聊天记录、Issue、记忆里，Agent 每次都要重新理解。
2. **判断不可比较**：不同 Agent 给出的结论停留在对话流里，无法并排审阅，也无法沉淀为决策。
3. **人机边界模糊**：Agent 是否正在处理？处理到哪一步？谁允许它改状态？没有清晰协议。
4. **历史不可追溯**：为什么这个需求被暂缓、是谁采纳了哪个方案，过几天就找不到。
5. **工具切换成本高**：为了把分析写回看板，用户自己在 Agent 与看板之间搬运文本。

### 1.2 产品定位

| 不是 | 是 |
| --- | --- |
| 通用项目管理/Jira 替代品 | 单用户需求决策台 |
| Agent 自动编码执行器 | Agent 分析接入层与回写协议 |
| 团队协作/权限系统 | 本地优先的个人工作区 |
| 多合一笔记工具 | 需求上下文、判断与决策的单一事实源 |
| SaaS 云端看板 | Windows 桌面应用 + 本机 HTTP/MCP Bridge |

### 1.3 设计原则

1. **意图先于流程**：先捕捉“要达成什么”，不强迫用户先填一套重型表单。
2. **判断可见**：Agent 分析必须成为可比较的卡片，而不是被埋没的聊天文本。
3. **人的裁决权**：Agent 可以建议、标记、写分析；是否采纳由人决定。Agent 改状态的权限默认显式、可关闭。
4. **本机可信**：默认离线，只监听 `127.0.0.1`，所有写操作要求令牌；不把数据发给任何第三方。
5. **少而准的信号**：颜色只承担语义；不依赖颜色单独传意。状态、优先级、Agent 身份都有文字或形状冗余。
6. **密度是功能**：这是一个每天开着的桌面工具；信息密度、键盘效率、扫描节奏优先于营销页式留白。
7. **诚实的状态**：加载、空、错误、离线、领取中、已过期，都要有语言，不用一个 spinner 掩盖。

## 2. 用户与任务

### 2.1 主要用户

**“多 Agent 的技术构建者”**：独立开发者、技术负责人、产品工程师。  
他们自己写代码，同时让 Claude Code / Codex / DeepSeek Harness 等处理分析、方案与实现。工作机是 Windows，习惯键盘、终端、MCP、快捷键。

### 2.2 核心任务（Jobs to be done）

- 当灵感或反馈出现时，**30 秒内记下来**，不丢上下文。
- 当要判断做不做、怎么做时，**把需求打包给 Agent**，拿回结构化分析。
- 当多个 Agent 给出不同结论时，**并排比较并采纳一个**。
- 当需求在流转时，**一眼看出哪里堵住、谁在领取、哪些等待验收**。
- 当事情做完后，**回看为什么这么决定**。

### 2.3 典型场景

1. **早晨 triage**：打开看板，收件箱 5 条；给其中 3 条打开“开放给 Agent”；在 Agent Desk 复制 Kickoff Prompt 到 Claude Code，让 Agent 批量分析。
2. **午后比较方案**：Claude Code 与 DeepSeek 对同一需求给出不同风险判断；打开详情页，逐条比对，采纳一方，把另一方保留为反例。
3. **实现中回看**：Codex 领取了需求并给出“needs-info”；用户回答开放问题，补充验收标准，再把需求移入进行中。
4. **周末复盘**：Activity 查看本周 Agent 提交了多少分析、哪些被采纳、哪些需求卡在待验收。

### 2.4 反用户 / 非目标

- 需要多人实时协作、评论 @、角色权限的团队场景。
- 需要云端同步、移动端、离线多设备场景（未来可扩展，不在 v0.1）。
- 需要自动执行代码修改的 Agent Runner（本版本只管分析回写，不代替 Agent 本身的执行环境）。

## 3. 核心概念

| 概念 | 含义 |
| --- | --- |
| **Requirement（需求）** | 一个可独立判断是否要做、如何验收的结果单元。编号形如 `REQ-003`。 |
| **Analysis（分析）** | 一个 Agent 对需求的可行性判断，包含结论、置信度、步骤、风险、开放问题、备注。可被人物采纳。 |
| **Claim（领取）** | 某个 Agent 对需求的短期占用，用于表达“我正在处理”，防止重复工作。带 TTL，可释放。 |
| **Agent Ready（开放给 Agent）** | 人类授予某需求可被 Agent 领取/分析的门槛。默认开启，可随时关闭。 |
| **Decision（采纳）** | 人类把某一条分析标记为当前采纳结论；需求最多一个采纳分析。 |
| **Activity（动态）** | 所有关键动作的审计记录：创建、状态变化、分析提交、采纳、领取、评论等。 |
| **Agent Bridge** | 本机 HTTP + MCP 接入层，供 Agent 读需求、领取、写分析、评论、改状态。 |

### 3.1 需求生命周期

固定的五阶段看板。Agent 分析是并行层，不是第六个阶段。

```text
收件箱 ──→ 已规划 ──→ 进行中 ──→ 待验收 ──→ 已完成
  │             │            │           │
  └─────────────┴──── 可任意回退 ──────────┘
```

- **收件箱**：尚未判断是否要做。允许 Agent 分析，用于辅助判断。
- **已规划**：方向已定，尚未启动。可交给 Agent 深化方案。
- **进行中**：正在实现或验证。Agent 可领取并写分析。
- **待验收**：实现/分析已完成，等待人确认。
- **已完成**：已验收。卡片降权显示，仍可回退或继续评论。

不采用“梳理中”作为第六列：分析状态由 `分析数量 / 领取状态 / 采纳状态` 表达，而不是再增加一列，避免看板臃肿。

### 3.2 优先级

| 值 | 显示 | 语义 |
| --- | --- | --- |
| `critical` | **P0** 紧急 | 阻塞或高风险；需要尽快判断 |
| `high` | **P1** 高 | 重要，当前周期优先 |
| `medium` | **P2** 中 | 正常排队 |
| `low` | **P3** 低 | 可等待，适合作为空隙任务 |

### 3.3 分析结论

| 值 | 显示 | 语义 |
| --- | --- | --- |
| `proceed` | 推进 | 建议做，并可给出方案 |
| `needs-info` | 补充信息 | 信息不足，列出需要回答的问题 |
| `defer` | 暂缓 | 可做，但不建议现在做 |
| `decline` | 不建议 | 与目标冲突、收益不足或风险过高 |

分析还有：`confidence`（0–100）、`estimatedEffort`（自由文本，建议 XS–XL）、`proposedSteps[]`、`risks[]`、`openQuestions[]`、`notes`（Markdown）。

### 3.4 状态所有权

| 数据 | 人类 | Agent | 系统 |
| --- | --- | --- | --- |
| 标题/描述/验收标准 | 读写 | 只读 | — |
| 状态/优先级/标签 | 读写 | 受设置限制，仅可改状态 | 迁移/导入时写 |
| 分析 | 可采纳 | 可创建 | 可校验/去重 |
| 评论 | 可创建 | 可创建 | 导入时保留 |
| 领取 | 可查看/强制释放 | 可领取/释放自己的 | TTL 到期自动失效 |
| Agent Ready | 读写 | 只读 | — |
| 令牌/端口 | 读写 | 只读（不暴露在 API） | 生成/轮换 |

## 5. 页面与区域规格

### 5.1 应用外框

```text
┌───────────────────────────────────────────────────────────────┐
│ Titlebar 40px · 品牌 · 本机状态 · 窗口控制                     │
├───────────────┬───────────────────────────────────────────────┤
│ Sidebar       │ Workspace                                     │
│ 232px         │ 页面头部 + 内容                                │
│ 深石墨         │ 暖纸色                                         │
└───────────────┴───────────────────────────────────────────────┘
```

- **Titlebar**：全宽 40px，深石墨底。左侧品牌 `PULSE`（自绘波形图标 + 字标）；中央显示当前工作区／页面（小号等宽字）；右侧最小化、最大化/还原、关闭。整条可拖动；控件 `-webkit-app-region: no-drag`。
- **Sidebar**：232px。导航 + 底部 Agent Bridge 状态卡。`< 1240px` 收缩为 76px 图标栏，保留 Tooltip 与状态点。
- **Workspace**：暖纸底，24–28px 内边距。所有页面共享同一顶部节奏：眉题 / 标题 / 操作 / 细分隔线。
- 窗口最小 1024×720，默认 1440×900。低于 1160px 详情右栏下沉为主列之后的卡片；低于 900px 不存在目标形态（桌面专用）。

### 5.2 侧栏

主品牌区：

- 波形图标 26×26：一条酸性柠檬折线穿过圆角方形。
- 字标 `PULSE`，Manrope 700，字距 +0.08em。
- 下方小字 `REQUIREMENT DESK`，等宽 10px，低对比。

导航（顺序）：

1. **看板** — 当前未完成需求数量 badge（仅在未选中时低对比显示）。
2. **Agent 工作台** — Bridge 在线点。
3. **动态** — 无 badge。
4. 分隔
5. **设置**（靠下，固定在底部组）

交互：

- 默认：图标与文字为低亮度灰绿；hover 背景轻微提亮。
- 选中：`--chrome-selected` 背景 + 左侧 2px 柠檬短线 + 文字变亮。
- 图标 18px，文字 13.5px；行高 40px；两侧圆角 8px。
- 所有导航是真实路由链接（`NavLink`），支持 `Ctrl+K` 跳转。
- 键盘：Tab 顺序 = 品牌 → 主导航 → 底部状态 → 设置。状态卡可点击进入 Agent 工作台。

底部 Bridge 状态卡：

- 深色内嵌面板；小圆点 + `Agent Bridge` + `在线 · 127.0.0.1:47321`。
- 离线时圆点变琥珀，文案 `已停止`；出错时变红，显示 `端口被占用`。
- 卡片高度约 74px；hover 提亮；点击进入 Agent 工作台。

### 5.3 看板页

#### 头部

```text
REQUIREMENT DESK / BOARD
需求看板                                   [搜索] [筛选] [新建需求]
12 个开放需求 · 3 个等待判断 · 2 位 Agent 在线
────────────────────────────────────────────────────────────
[看板 | 清单]  活跃筛选 chips（如：P0、开放给 Agent）×清除
```

- 眉题：等宽 10px，字距 0.08em，颜色 `--ink-3`。
- 标题：32px，Manrope 650 + Noto Sans SC 600，字距 -0.03em。
- 摘要：13px，`--ink-2`；数字使用 tabular-nums。
- 主操作“新建需求”：柠檬底 + 深墨字 + `Plus` 图标。次操作：搜索按钮、筛选按钮（带激活计数点）。
- 视图切换：分段控件，看板 / 清单。切换后记住（localStorage）。
- 活跃筛选以 chip 展示，紧邻视图切换器；可单个移除或全部清除。

#### 看板

- 横向容器：`overflow-x: auto`，五列 `minmax(220px, 1fr)`，gap 12px。
- 列：非卡片容器，`--surface-sunken` 背景、圆角 14px、内边距 10px。顶部粘性列头。
- 列头：
  - 左侧：状态色 6×6 圆点（非唯一信号）+ 中文名 + 等宽计数。
  - 右侧：`+` 按钮，在该状态新建需求（打开 Dialog 并预选状态）。
  - 下方 1px 分隔线。
- 卡片：
  - 背景 `--surface`，1px 半透明描边，圆角 12px，内边距 12px。
  - 顶部一行：编号 `REQ-003`（JetBrains Mono 10.5px，字距 .04em，`--ink-3`）+ 优先级 chip `P1`（语义色 + 文字）+ 拖拽手柄（hover 才显示，键盘可聚焦）。
  - 标题：14px / 1.45 / 600，最多 3 行后省略。
  - 底部 meta 行：标签（最多 2 个 + `+n`）、Agent 头像组、分析数（对话气泡/星形图标）、截止日（逾期红色 + 文字“逾期”）。
  - 领取中：卡片底部出现一条 `Agent` 存在条：Agent monogram + `Claude Code 正在分析` + 到点时间；用等宽时间与脉动点。
  - hover：轻微上抬 1px、描边增强；不改变布局。focus-visible：2px 柠檬描边 + 2px offset。
  - 点击（非拖拽）打开详情；`Enter` 也可打开（卡片为可聚焦 button-like 容器，使用 `<article>` 内主链接或可点击标题？统一使用 `<button class=card-hit>` 会破坏内嵌按钮。采用卡片根 `<article>`，标题为 `<Link>`，卡片点击通过 onClick 但非按钮？为可访问性，卡片主体是链接；菜单和拖拽手柄独立按钮。整卡点击可用 `onClick` 并配合键盘链接。详见技术设计。）
- 空列：虚线边框的空状态，文字“还没有需求” + 次要按钮“添加一条”。仅在搜索/筛选无结果时不同文案。
- 拖拽：
  - 手柄拖起卡片，DragOverlay 显示略放大 1.02 的影子卡片。
  - 跨列移动时目标列背景提亮，显示插入位置线。
  - 同一列可重排。
  - 不能用拖拽的用户：卡片菜单“移动到…”；详情状态菜单。
- 滚动：列内容独立滚动？为避免嵌套滚动灾难，整页滚动、列头 sticky 于 board 区域。看板高度填满窗口，列内部纵向滚动，列头不滚。设计：board 容器 `flex:1; min-height:0`；每列 `overflow-y:auto`，列头 sticky。列内滚动在桌面端可接受。
- 列底：`+ 添加需求` 幽灵按钮，紧跟最后一张卡。

#### 清单视图

- 语义化 table：编号、标题、状态、优先级、Agent、最后更新。表头可排序（updatedAt / priority）。行高 52px。
- 行：hover 背景提亮；点击整行打开。状态 chip、Agent 分析数、领取状态。
- 列表为空时同看板空状态。表格支持键盘 Tab 到行内标题链接。
- 筛选与看板共享状态（本次会话）。

#### 筛选

筛选 Popover（Radix Popover）：

- 优先级：多选 P0/P1/P2/P3。
- Agent：全部 / 开放给 Agent / 当前被领取 / 已有分析。
- 清除全部。
- 筛选按钮显示激活数量 badge；看板头部展示活跃筛选 chips。

搜索：

- 看板页搜索按钮打开命令面板（同一 UI，输入即搜索），而不是单独搜索框，减少头部拥挤。`Ctrl+K` 亦可。
- 结果包含需求编号、标题、状态；选中跳转详情。

### 5.4 新建/编辑需求 Dialog

- 尺寸：`min(720px, calc(100vw - 56px))`，最大高度 `calc(100vh - 80px)`，内部滚动。
- 头部：眉题 `CAPTURE` 或 `EDIT`；标题“新需求”/“编辑需求”；关闭按钮。
- 引导句：“先写下你要达成什么。细节可以之后再补。”
- 字段：
  1. **标题**（必填，单行，自动聚焦，1–160 字）。错误就地显示。
  2. **描述**（Markdown，6 行，可选）。占位示例：“现在是什么情况？为什么值得做？”
  3. **验收标准**（Markdown，4 行，可选）。占位：“怎样算完成？列出可检查的结果。”
  4. 一行两列：**优先级**（4 个 radio-chip：P0/P1/P2/P3）、**状态**（五阶段下拉）。
  5. **标签**（输入后 Enter/逗号添加，最多 8 个；chip 可移除；重复忽略）。
  6. 可折叠“更多信息”：来源、截止日期、预估工作量。
  7. **开放给 Agent** Switch，默认开；说明“Agent 可领取并提交分析；你仍决定是否采纳和推进。”
- 底部固定操作条：取消 / 保存按钮。新建时文案“加入收件箱”（即使状态是其他列，以选中状态为准，按钮显示“创建需求”）。`Ctrl+Enter` 保存。
- 校验：标题非空；标题过长；端口等不在此。
- 关闭：Esc / 取消 / 点遮罩；有未保存内容时，Radix 默认直接关闭会有丢失风险。设计选择：当用户修改过内容时，关闭前显示内联确认条：“有未保存的更改。 继续编辑 / 放弃”。按 Esc 先显示确认条而不是直接关。
- 编辑同样表单，状态/优先级修改写入审计。
- 焦点陷阱与返回由 Radix Dialog 处理；保存成功关闭后焦点回到触发按钮或新建入口。

### 5.5 需求详情

布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ ← 看板   REQ-003              [状态▾] [P1▾] [⋯]             │
│ 标题（可编辑入口）                                             │
│ 标签 · 创建于 · 更新于 · 已采纳: Codex 分析                   │
├─────────────────────────────────────────┬────────────────────┤
│ 需求内容                                 │ Agent 交接          │
│ - 描述 (Markdown)                        │ - 开放给 Agent      │
│ - 验收标准                               │ - 领取状态          │
│ - Agent 分析列表                         │ - 复制任务提示词     │
│ - 评论                                   │ - 打开 Agent 工作台  │
│                                          │ 元数据               │
│                                          │ 最近动态             │
└─────────────────────────────────────────┴────────────────────┘
```

- 返回链接 `← 看板`，保留看板滚动位置（hash 路由 + session state）。
- 标题区：标题 30–34px，允许换行；右侧“编辑”ghost 按钮或标题 hover 显现。为简单可靠，标题始终显示“编辑”按钮，不做双击隐藏操作。
- 状态与优先级为下拉；变更即时保存并 toast。状态更改会写 activity。
- `⋯` 菜单：编辑、复制链接（应用内 hash 链接）、删除（危险，打开 AlertDialog 确认，确认按钮为危险红）。删除后返回看板。
- 内容卡：
  - “需求”卡：描述 Markdown；为空时显示柔和的空文案“还没有详细描述。编辑补充背景，Agent 才能给出更可靠的判断。”
  - “验收标准”卡：Markdown checklist 渲染；为空时同样提示。
- **Agent 分析区**：
  - 区域头：`Agent 分析` + 数量 + “复制交接提示词”。
  - 空：带波形装饰的提示“还没有 Agent 判断” + 两步说明 + 按钮“复制任务提示词”；若未开放给 Agent，提示先开启。
  - 分析卡：见组件规格。
  - 采纳：点击“采纳此分析” → 该卡顶部出现实心柠檬色 decision strip（文字“已采纳”，含按钮“取消采纳”）。需求头部显示采纳指向。
  - 排序：最新在前；采纳的分析置顶并带标记。允许多个历史分析并列，不删除。
- **评论**：
  - 评论项：作者 monogram（人/Agent 区分）、姓名、相对时间、Markdown 内容。
  - 输入：多行 textarea + “添加评论”按钮；`Ctrl+Enter` 提交；提交后清空并保留焦点。`aria-live` 宣布成功。
- 右栏：
  - **Agent 交接卡**（`--surface-sunken` 或白色卡）：
    - 标题 `AGENT HANDOFF`；开关“开放给 Agent”。
    - 若领取中：`Claude Code` 正在分析 + 剩余时间；按钮“释放领取”（人工可强制释放，二次确认可选）。
    - 若未领取且开放：状态文案“等待 Agent 领取”。
    - 主操作 “复制任务提示词”；次操作 “复制需求简报”（下拉菜单）。
    - 提示：需要先在 Agent 工作台配置 MCP。
  - 元数据 dl：编号、创建者、来源、截止日期、预估工作量、创建/更新时间。
  - 最近动态：该需求的 5 条 activity；链接到完整 Activity 页面并带筛选（可选）。
- 滚动：主区域滚动；右栏 sticky top 24px，若内容超出视口则独立滚动（max-height）。<1160px 时右栏沉下，不再 sticky。
- 状态不阻塞：领取过期时 UI 自动视为未领取，不做后台秒级轮询；打开详情时按当前时间计算。

#### 分析卡详细规格

```text
┌─────────────────────────────────────────────────┐
│ [CC] Claude Code · claude-sonnet    12 分钟前    │
│      结论 chip: 推进   置信度 72%   ─────●──    │
│                                                 │
│ 摘要文本，最多 6 行，是 Agent 的一句话判断。         │
│                                                 │
│ 建议步骤  1. ...   2. ...   3. ...              │
│ 风险      • ...    • ...                         │
│ 开放问题  • ...                                  │
│ 备注（Markdown，可折叠，默认展开 4 行后渐隐）       │
│                                                 │
│ [采纳此分析]            [复制原文]               │
└─────────────────────────────────────────────────┘
```

- Agent 身份色只用于 monogram 边框/小点与“采纳”标记的附属线，不整卡着色。
- 结论 chip 与置信度并排；置信度用数值 + 细 meter，不只依赖颜色。
- 风险按行显示，用 `AlertTriangle` 小图标；开放问题用 `HelpCircle`。
- `采纳此分析` 在已采纳时变为 "已采纳" 状态禁用 + "取消采纳" ghost。
- 复制原文复制 JSON 的格式化分析，不含 UI。
- 分析卡进入视口时不做滚动动画；新增时顶部一条 1.2s 的柠檬左边线亮起后淡出（减少动态模式下直接显示）。

### 5.6 Agent 工作台

目标：让用户 2 分钟内把 Agent 接上，并持续知道“谁在线、最近写了什么”。

```text
AGENT DESK / BRIDGE
Agent 工作台
把需求交给合适的判断者。                    [重启 Bridge]
────────────────────────────────────────────────────────────
┌──────────────────────────────┐  ┌─────────────────────────┐
│ Agent Bridge                  │  │ 当前在线                 │
│ 在线 · 127.0.0.1:47321        │  │ Claude Code  刚刚       │
│ [复制 URL]                    │  │ Codex        8 分钟前   │
│ Token ••••••••  [显示][复制]   │  └─────────────────────────┘
│ [停止 Bridge]                 │  ┌─────────────────────────┐
│ 安全检查：只监听本机 / 令牌鉴权 │  │ 最近分析                │
└──────────────────────────────┘  │ ...                     │
┌────────────────────────────────────────────────────────────┐
│ 接入 Agent   [Claude Code | Codex | DeepSeek / 通用 | HTTP]  │
│ 步骤 1  安装/打开 Agent                                      │
│ 步骤 2  将配置加入 ...（代码块） [复制]                       │
│ 步骤 3  在 Agent 里说：“读取 Pulse 看板，分析 REQ-001”         │
└────────────────────────────────────────────────────────────┘
```

- 顶部主卡为深石墨“仪表盘”卡，柠檬色状态灯；这是页面唯一的深色块，形成视觉锚点。
- “在线”定义：Bridge HTTP server 正在监听；不是 Agent 心跳。活跃 Agent 用最近写入时间推导，标注“最近活跃”，避免误称在线。
- Bridge 卡：
  - URL 可复制，等宽显示。
  - Token 默认遮罩，显示按钮需点击；复制不需要展开。
  - 轮换 Token 为危险操作，弹确认，说明现有配置将失效。
  - 停止/启动开关。
- 接入 Tabs：
  - Claude Code：`.mcp.json` 片段 + 用户级命令示例。
  - Codex：`~/.codex/config.toml` 片段。
  - DeepSeek / 通用 MCP：通用 `mcpServers` JSON + 环境变量说明。
  - HTTP：curl 读取/领取/提交分析的最小例子。
  - 每个代码块有复制按钮；强调“令牌只存在本机配置中，不要提交到仓库”。
  - 配置中的绝对路径与端口/token 由应用现场生成；开发者可读但不要硬编码。
- “Agent 工作流”三栏说明：读取 → 分析 → 回写。展示 MCP 工具名。
- 活跃 Agent 列表：monogram、名称、最近活跃、分析/评论计数。无数据时提示“还没有 Agent 写过东西”。
- 最近分析：最多 5 条，Agent、需求编号、结论、时间；点击跳详情。
- 连接清单：Bridge 在线 / MCP 文件存在 / Token 已生成。若 MCP 文件缺失，显示构建提示（开发环境）。
- 安全提示：
  - 只绑定 `127.0.0.1`；局域网不可访问。
  - Token 存在本机应用数据目录，不参与导出。
  - Agent 不能读取其他本机文件；Bridge 只提供需求数据。
- 若 Bridge 无法启动：红/琥珀内联错误卡显示原因（端口占用、权限），提供“改端口”链接到设置。

### 5.7 动态

- 页头：`ACTIVITY / 本地审计日志`，标题“动态”。
- 筛选：全部 / Agent / 人工 / 系统（segmented or chips）。
- 时间分组：今天、昨天、日期（本地时区）。
- 条目：时间、actor monogram、句子、需求编号链接。
  - 示例：“Claude Code 提交了对 REQ-003 的分析：推进。”
  - 系统：“Bridge 启动，端口 47321。”
- 空：没有匹配动态；给出清除筛选。
- 最多加载最近 200 条快照；更多历史保存在完整 store 中（v0.1 只保留有界记录）。

### 5.8 设置

采用“工作流设置页”布局：单列约 720px + 侧边目录（可省略），每个设置块为独立卡，显式保存按钮只在需要时出现。

- **外观**：主题三选一（跟随系统 / 浅色 / 深色），三张缩略预览卡（浅纸、深石墨、系统 split）。切换即时应用；system 跟随 Windows 主题。
- **身份**：你的显示名（默认“本地用户”）。用于 activity / 评论署名。失焦或按钮保存。
- **Agent Bridge**：
  - 启用开关（即时保存并重启）。
  - 端口输入（1024–65535；保存并重启，显示当前状态）。
  - 允许 Agent 修改需求状态（默认开）；解释“仍不可编辑标题/描述”。
  - 桌面通知：Agent 提交新分析时（默认开）。
  - Token 状态与“前往 Agent 工作台”。
- **数据**：
  - 数据目录路径 + “打开文件夹”。
  - 导出完整数据（JSON，不含 token）。
  - 导入数据（JSON，覆盖当前工作区；先备份；确认对话框）。
  - 存储说明：本地 JSON、原子写入、保留最近 10 个备份（桌面文字）。
- **关于**：版本、构建类型、GitHub 仓库链接、快捷键说明入口。开源许可证 MIT。

### 5.9 命令面板

- 触发：`Ctrl+K`（Windows）/ `Cmd+K`（macOS 兼容时）。
- 宽度 620px，顶部输入，`Esc` 关闭，`↑/↓` 移动，`Enter` 执行。
- 分组：
  1. **操作**：新建需求、打开 Agent 工作台、打开动态、切换主题、导出数据。
  2. **需求**：按更新排序前 6 条匹配项；显示编号、标题、状态。
- 无结果：文案 + 新建需求入口。
- 底部：键盘提示 `↑↓ 选择` `↵ 打开` `esc 关闭`；右侧可显示 `Pulse Command`。
- 底层使用 `cmdk`，Dialog 语义与焦点由 Radix 管理。

### 5.10 删除确认

- AlertDialog 尺寸 400–440px。
- 标题“删除这条需求？”
- 正文包含需求编号与标题，说明“分析、评论与历史也会一并删除。此操作无法撤销。”
- 取消为默认焦点；危险按钮红底白字。
- 确认后关闭；若当前在详情页，返回看板。

## 6. Agent 协作体验

### 6.1 人的工作流

1. 记下需求 → 打开“开放给 Agent”（默认开）。
2. 打开详情/Agent 工作台 → 复制任务提示词。
3. 在 Claude Code / Codex / DeepSeek 会话中粘贴，Agent 通过 MCP 读取、领取、分析、回写。
4. 回到看板，实时看到领取状态与分析；收到桌面通知（若离开）。
5. 比较分析，采纳一个，按需要更新状态/补充问题。

### 6.2 Agent 的工作流（协议层）

```text
list requirements (agentReady, priority)
  → get requirement
  → claim (TTL 90 min)
  → analyze locally
  → submit analysis (idempotency-key)
  → optionally add comment / update status
  → release claim
```

- 强制约束：提交分析时，如果需求已有其他 Agent 的有效领取 → 409，不出分析卡。
- 领取 TTL 到期自动作废；人可在 UI 强制释放。
- 同一 Agent 重复领取刷新 TTL。
- 采纳只由人或 UI 触发，Agent 不能采纳自己的分析。
- Agent 提交分析不自动改变需求状态；改状态需单独的显式操作 + 设置许可。
- 所有 Agent 写入都记录 actor（name/kind/model）与 activity。

### 6.3 面向前端的语言

- 不展示“prompt engineering”这类内部词。
- 用“任务提示词 / 需求简报 / 交接”。
- 状态指示使用：`等待领取`、`正在分析`、`领取已过期`、`分析已提交`。
- Agent 身份标签：`Claude Code`、`Codex`、`DeepSeek`、`Agent`；颜色只作辅助。

## 7. 视觉系统

### 7.1 方向与反方向

**方向**：一台被认真设计过的桌面仪器。暖纸色工作面、深石墨框架、柠檬信号色、精确的等宽编号、紧凑的排版节奏、几乎不用的阴影。像实验室的索引卡柜，而不是 SaaS 营销页。

**拒绝的默认**：

- 深色背景 + 紫蓝渐变光晕 + 玻璃拟态卡片。
- 五张完全相同的圆角 KPI 卡。
- 大量胶囊 chip、渐变文字、悬浮大圆角。
- 把 Agent 标识做成彩虹色块。
- 用 emoji 当图标。

### 7.3 字体

| 层级 | 字体 | 规格 |
| --- | --- | --- |
| Latin display / UI | **Manrope Variable** | 标题 600–700，正文 450–600 |
| 中文正文 / UI | **Noto Sans SC Variable** | 400–600，跟随 Windows 清晰渲染 |
| 编号 / 数据 / 时间 | **JetBrains Mono Variable** | 10–13px，字距 0.02–0.06em，`tabular-nums` |
| 回退 | `"Microsoft YaHei UI", "PingFang SC", system-ui, sans-serif` | — |

字号阶梯：

- 页面标题 30–32px / 1.15 / -0.03em
- 区块标题 18–20px / 1.3 / -0.015em
- 卡片标题 14px / 1.5 / -0.005em
- 正文 13.5–14px / 1.6
- 次要元数据 11.5–12.5px / 1.4
- 等宽编号 10.5–11px / 1.2 / +0.04em
- 极小大写标签（仅限一处）10px / 1.2 / +0.08em

字体包随应用打包，不依赖网络。中文覆盖率优先。

### 7.4 间距、形状、层级

- 4px 基础网格：4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48。
- 页面内边距：28px 水平（<1240px 时 22px）。
- 卡片内边距：12–16px；看板卡片 12px。
- 圆角：卡片 12px、列容器 14px、输入/按钮 8px、Dialog 18px、菜单 10px。禁止把所有东西做成 pill。
- 阴影：
  - 卡片 `0 1px 0 rgba(20,24,16,.03), 0 8px 24px -24px rgba(20,24,16,.35)`
  - 弹层 `0 24px 64px -28px rgba(8,12,6,.55), 0 2px 8px rgba(8,12,6,.08)`
  - 深色主题以黑色阴影 + 表面明度区分。
- 边框以半透明细线为主；hover 从 `--border` 提升到 `--border-strong` 或柠檬 30% 混合，不硬编码灰。
- 背景不使用渐变、无玻璃模糊（blur），除系统不支持透明时的纯色回退。页面边缘不加纹理/噪点（产品界面不继承品牌页的 grain）。

### 7.5 视觉签名

- **Pulse mark**：圆角方框内的折线，键盘焦点/在线状态时线条发光（CSS `filter: drop-shadow` 一次，不循环）。
- **列头像信号**：列头的状态点 + 等宽计数，像仪器刻度，而不是花哨徽章。
- **Agent monogram**：两位字母缩写放在 24px 圆角方形，边框使用 Agent 身份色，底色是身份色 10% 混合。
- **编号主导航**：所有需求编号、时间、快捷键用 JetBrains Mono，与正文形成“工具感”对比。
- **决策条**：采纳分析后在卡顶出现的窄柠檬条是唯一使用高饱和块的装饰，表达“人已裁决”。

## 9. 交互契约

### 9.1 看板拖拽

- **目的**：调整需求状态与顺序。
- **触发**：拖动卡片手柄，或聚焦手柄后 `Space` 拾起，方向键选择位置，`Space` 放下，`Esc` 取消。
- **过程**：卡片轻微放大 1.02、阴影加深；目标列背景提亮；插入位置显示 2px 柠檬线。跨列只在放下时提交。
- **结果**：状态/顺序立即乐观更新；主进程持久化并刷新快照。失败：回退到之前位置 + 错误 toast。
- **替代**：卡片菜单“移动到…”（单选列表），详情状态菜单；不依赖拖拽。
- **限制**：已完成列可拖出、可拖入；不做跨窗口。Hover 才显示手柄但键盘可 Tab 到它。

### 9.2 新建需求

- **触发**：`Ctrl+N`、页面按钮、列头 `+`、命令面板、空状态。
- **过程**：Dialog 淡入缩放（0.985→1，180ms）；标题自动聚焦。列头 `+` 会预设状态。
- **结果**：保存后关闭，toast `已加入收件箱 · REQ-012`；看板刷新并滚动到该卡（可选：高亮 1.2s）。
- **中断**：有改动时 Esc/取消先显示内联“放弃更改？”确认；再次 Esc 才关闭？规则：第一次 Esc 显示确认条；点“放弃”或再次 Esc 关闭。
- **焦点**：关闭后回到触发按钮；若触发元素消失，回到主标题。
- **错误**：标题校验就地呈现；主进程保存失败保留表单与内容，显示错误条 + 重试。

### 9.3 命令面板

- **触发**：`Ctrl+K`、看板搜索按钮。
- **过程**：遮罩淡入，面板从 8px 下方滑入（respect reduced motion），输入框自动聚焦。
- **结果**：选择需求 → 跳转详情；选择动作 → 执行并关闭；`Esc` 关闭并把焦点还给触发元素（若不存在则给 `main` 的第一个可聚焦）。
- **输入法**：`compositionstart/end` 期间不处理 Enter 导航，避免中文输入误触发。
- **空**：搜索无结果时仍保留“新建需求”动作。

### 9.4 采纳分析

- **触发**：分析卡“采纳此分析”。
- **过程**：按钮短暂禁用；成功后在卡顶部出现决策条并更新需求头部；toast。无需确认。
- **结果**：需求 `acceptedAnalysisId` 指向该分析；其他分析保留但取消采纳标记。
- **反悔**：决策条“取消采纳”立即恢复，不过需要二次确认？取消采纳是可逆、低风险操作，不做确认。
- **冲突**：若主进程报错（需求已删除/分析不存在），toast 错误并刷新快照。

### 9.5 领取与过期

- **展示**：领取中卡片显示 Agent 名称与剩余时间；时间取本地时钟。
- **实时**：每 30 秒刷新一次页面“当前时间”状态（不请求数据）；超过 TTL 即隐藏领取。下一次任意数据刷新会清理过期 claim。
- **人工释放**：详情右栏“释放领取”，用于 Agent 卡死/误领。无需二次确认但 toast 说明“已释放，Agent 的写入会被拒绝”。
- **Agent 视角**：领取被占用时 409 返回，MCP 输出错误及当前领取者。

### 9.6 主题切换

- **触发**：设置三张卡 / 命令面板动作 / 系统主题变化（当设为系统）。
- **过程**：CSS 变量立即切换；只在 `background-color/color/border-color` 上做 140ms 过渡，避免全属性动画。
- **结果**：主进程持久化主题；窗口背景色同步更新，防止闪白/闪黑。
- **系统**：`prefers-color-scheme` 监听；手动主题覆盖系统。

### 9.7 自动保存

- 详情页的状态、优先级、Agent Ready、采纳为即时命令（无“保存”按钮）；更新后 toast 或静默（低频字段静默 + 状态圆点短暂闪绿）。
- Dialog 内的字段为显式保存（避免中文输入过程中频繁 IPC）。
- 评论提交为显式按钮 / `Ctrl+Enter`；失败保留文本。

## 10. 动效

动效只表达反馈、空间关系与层级，不承担业务状态。

| 场景 | 路径 | 时长/缓动 | 减少动态 |
| --- | --- | --- | --- |
| 导航选中 | 背景色 + 2px 指示条 | 160ms `cubic-bezier(.2,.8,.2,1)` | 直接显示 |
| 卡片 hover | translateY(-1px)、边框色 | 120ms ease-out | 仅边框/颜色 |
| 拖拽拾起 | scale(1.02)、阴影 | 140ms | 无缩放 |
| 弹层出现 | opacity + scale(.985→1) + 6px 上移 | 180ms | 立即显示 |
| 弹层消失 | opacity + scale(1→.99) | 140ms | 立即消失 |
| Toast | 从下方 8px + fade | 180ms 进入 / 140ms 退出 | 直接显示/消失 |
| 分析到达 | 左侧 2px 柠檬条亮起 1.2s 后淡出 | 1.2s | 静态条 |
| 主题切换 | 颜色 140ms | 140ms | 立即 |

- 所有过渡只动 `transform / opacity / color / background-color / border-color`，不动 width/height/top/left。
- 悬停效果只在 `(hover:hover) and (pointer:fine)` 下启用。
- `prefers-reduced-motion: reduce` 下全局近似关闭：`animation-duration: .01ms !important; transition-duration: .01ms !important; scroll-behavior: auto`。业务状态与反馈不变。
- 不使用滚动视差、自动轮播、无限脉动。Agent 状态点仅在 “正在领取” 时使用 1.6s 呼吸，减少动态下静止。
- 拖拽中断：Esc/指针释放均结束 overlay，不留下不可见遮罩。

## 11. 可访问性

目标：WCAG 2.2 AA 的实际行为，不声称完整认证。

- **键盘完整**：所有操作可不用鼠标完成，包括移动状态、打开菜单、关闭弹层、提交表单、采纳分析、复制提示词。
- **焦点**：全局 `2px solid var(--focus)` + `outline-offset: 2px`；粘性元素不遮挡焦点；弹层关闭后焦点回到触发元素或稳定的替代元素。
- **语义**：
  - 看板列使用 `section` + `aria-labelledby`；卡片标题为主链接。
  - 状态/优先级有文字；不靠颜色。
  - 页面标题层级唯一 `h1`。
  - 表单 label 显式关联，错误 `aria-describedby` + `aria-invalid`。
  - 评论/表单错误/成功使用 live region。
- **拖拽替代**：菜单与详情状态控件；拖拽手柄有 `aria-label`。
- **对比度**：文档 §7.2 列出的文本组合 ≥4.5:1；焦点/图形 ≥3:1。深色模式使用独立色值，不盲目反转。
- **减少动态**：见 §10；无自动播放。
- **触控/命中**：桌面按钮最小 28×28，主要操作 36px；列表行可点击高度 ≥48px。窗口最小 1024px，无手持版本。
- **缩放/回流**：应用随浏览器缩放；布局在 1024–1920 宽度验证；不设死宽导致页面级横向滚动；看板本身允许有意横向滚动。
- **辅助技术待验证**：Narrator 实际朗读、第三方屏幕阅读器、中文输入法细节（已做 composition 规避），在交付时列为未验证项，不能声称通过。

## 12. 状态与反馈

### 12.1 空状态

- 看板无数据：几何波形插画（内联 SVG）+ “还没有需求落在桌上” + “把第一条想法写下来，之后再判断。” + 主按钮。
- 筛选无结果：“没有符合当前筛选的需求” + 清除筛选。
- 分析无数据：“还没有 Agent 判断” + 说明三步 + 复制提示词/打开 Agent 工作台。
- 动态无数据：“这里还很安静。创建需求或让 Agent 提交分析后，动作会出现在这里。”
- 活跃 Agent 无数据：“还没有 Agent 写过东西。配置 MCP 后，它们会出现在这里。”
- Agent 配置缺失（开发环境）：显示 MCP 文件路径 + 运行 `npm run mcp:build` 的提示。

### 12.2 加载

- 首次启动：App Shell 立即渲染，内容区显示与卡片同高的骨架（不转 spinner）。
- 弹层/按钮异步：按钮显示 inline spinner，禁用；超过 300ms 才显示，避免闪烁。
- 不阻塞：IPC 本地通常 <50ms，极少出现 loading；仍保留骨架以防文件大。

### 12.3 错误

- **主进程错误**：以结构化 `{code,message}` 返回，UI toast + 可重试动作；不吞异常。
- **Bridge 启动失败**：Agent 工作台红/琥珀内联卡，显示 `EADDRINUSE` 转成可读文案“端口 47321 已被其他应用占用，请在设置中换一个端口”。
- **数据文件损坏**：启动时备份损坏文件到 `backups/corrupt-<timestamp>.json`，初始化空工作区并显示提示；不静默丢失。
- **Agent 写入被拒**：HTTP 409/401，MCP 返回原文；UI 显示领取者或权限提示。
- **保存失败**：乐观更新回滚；表单保留输入。

## 13. 文案原则

- 直接、具体、短句；不卖萌，不写“赋能/闭环/沉浸式”。
- 状态文案使用动词或明确结果：“等待 Agent 领取”“已采纳 Codex 分析”。
- 空状态给出下一步，而不是只写“暂无数据”。
- 不使用 em dash 作为装饰；中文标点使用全角。
- 术语保持一致：需求、分析、采纳、领取、开放给 Agent、Bridge、Agent 工作台。
- 英文技术名词保留原文：Markdown、MCP、HTTP、Token、TTL。

## 14. 验收

- 一个第一次见产品的人能说清：看板在哪里、如何新建需求、如何把需求交给 Agent、如何采纳分析。
- 在 1440×900 与 1024×768 下，核心任务（新建、打开详情、采纳、复制提示词）不需要页面级横向滚动（看板列自身可横滚）。
- 键盘完成：打开命令面板 → 新建需求 → 保存 → 打开详情 → 采纳分析 → 返回。
- 浅/深主题下所有正文与元数据文本对比度 ≥4.5:1（以实际渲染采样验证）。
- 减少动态模式下没有位移动画，弹层即时出现，焦点正常。
- Agent 接入文档可在 2 分钟内让一个 MCP 客户端完成一次真实分析回写。
- 任何 Agent 不能在没有人工点击的情况下采纳分析、修改标题/描述，或绕过 Token。
